- Dueño: Codex

- Feature: `docs/engineering/features/F-018.json`
- Módulos permitidos: `AGENTS.md`, `docs/engineering/FEATURES.md`, `docs/engineering/features/F-018.json`, `docs/engineering/tasks/T-018.md`, `.github/workflows/ci.yml`, `.github/workflows/sync-merged-features.yml`, `package.json`, `scripts/sync-merged-features.mjs`, `scripts/sync-merged-features.test.mjs`.
- Objetivo: después de un merge humano a `main`, actualizar automáticamente los features `done` a `merged`, sin otra PR de mantenimiento.

## Contrato previo a cambios compartidos

El workflow se activa por `push` a `main` y opcionalmente de forma manual para reintentos. Lee solo registros `done` cuyo campo `pr` apunta exactamente a una PR de este repositorio. Consulta la API oficial de GitHub y exige `merged_at`, `base.ref === "main"`, repositorio base y origen idénticos, `head.ref` igual a la rama del feature y presencia exacta de su `F-###.json` en los archivos de la PR (con paginación). Solo entonces cambia `status` a `merged` y agrega evidencia de número, fecha y commit del merge. Nunca marca `merged` por una PR fusionada a otra rama (como ocurrió con PR #3), por otra PR del mismo repo, ni toca features en otro estado; tampoco aprueba ni fusiona PR.

El workflow usa `contents: write` y `pull-requests: read` solo en este job. Relee `main` antes de escribir, instala dependencias del lockfile vigente en cada intento y reintenta un push no fast-forward; valida los gates del registro y los cuatro gates de calidad antes de publicar el commit de metadatos. No se usa PAT ni secretos nuevos. Un push hecho con `GITHUB_TOKEN` no inicia otro CI, de modo que el propio workflow debe validar el commit.

## Aceptación

- Pruebas: merge a `main`, merge a otra rama, PR abierta, URL ajena, rama/archivo ajenos, paginación, estado distinto de `done`, ejecución repetida y respuestas API inválidas.
- `npm run features:check`, `npm run features:sync:test`, lint, typecheck, tests y build verdes.
- Tras el merge humano de esta PR, su push a `main` actualiza también F-004, cuya PR #7 ya fue fusionada a `main` pero sigue en `done`.
- Revisión ajena, CI verde y handoff antes de `done`; el merge de esta PR sigue reservado al humano.
