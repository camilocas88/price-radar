# T-020 — Endpoint /api/health/sources por conector

- Feature: F-017
- Dueño: Claude
- Rama: `feature/t-020-sources-health`
- Estado: `claiming` → `in_progress` tras publicar draft PR.

## Objetivo

Exponer un endpoint JSON con el estado por conector de datos. Sirve como base para badges en la landing y para monitoreo externo. Anticipa parte de F-012 (observabilidad) sin bloquearlo.

## Alcance

- Nuevo módulo `src/lib/source-health.ts` con:
  - Tipo `SourceHealth = { source, status: 'ok'|'degraded'|'down', latencyMs, checkedAt, message? }`.
  - `checkMercadoLibreHealth({ fetchImpl, timeoutMs })` que golpea un endpoint barato (`/sites/MCO`) y clasifica según latencia.
- Nuevo endpoint `GET /api/health/sources` que ejecuta todos los checks en paralelo con `Promise.allSettled` y responde 200 siempre.
- Pruebas para el check de Mercado Libre con `fetch` mockeado (ok, degraded, down por error, down por timeout).

## Fuera de alcance

- Persistencia de historial de salud (F-006/F-012).
- Nuevos conectores; hoy sólo Mercado Libre.
- Cambios en `src/app/api/offers/route.ts` o `page.tsx` (reclamados por F-004).

## Contrato

Response body:

```json
{
  "checkedAt": "2026-09-30T00:00:00.000Z",
  "sources": [
    { "source": "mercadolibre", "status": "ok", "latencyMs": 142, "checkedAt": "2026-09-30T00:00:00.000Z" }
  ]
}
```

Estados:
- `ok` — latencia < 1500 ms.
- `degraded` — latencia entre 1500 y 3000 ms, o respuesta no-2xx recuperable.
- `down` — timeout, error de red o 5xx.

## Riesgos

- `sites/MCO` puede cambiar de latencia por región; los umbrales son heurísticos y se documentan en el módulo.
- El endpoint no debe filtrar credenciales del `Authorization`; el check no envía token porque el ping es público.
