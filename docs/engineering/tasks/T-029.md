# T-029 — Descubrimiento web de productos en varias tiendas

- Dueño: Codex
- Estado: `done` (antes del merge humano)
- Rama: `feature/t-029-public-catalog-search`
- PR: https://github.com/camilocas88/price-radar/pull/21
- Feature: F-022 (`docs/engineering/features/F-022.json`)
- Módulos permitidos: los enumerados en `docs/engineering/features/F-022.json`.
- Objetivo: que una búsqueda libre como «carpas» encuentre páginas de producto de varias tiendas y muestre sus precios publicados sin depender de Mercado Libre.

## Contrato previo a implementación

Se consulta Brave Search API mediante `BRAVE_SEARCH_API_KEY`, con ubicación Colombia y tres consultas acotadas por búsqueda del usuario (Éxito, Falabella y web general) para favorecer diversidad de tiendas; esto consume tres consultas facturables del proveedor. El proveedor devuelve URLs de descubrimiento, no precios autoritativos. Solo se inspeccionan URLs HTTPS de tiendas colombianas permitidas; sin redirecciones, credenciales ni parámetros de usuario, y con límites de tiempo, cantidad y bytes. El precio COP se toma de JSON-LD `Product/Offer` público y vigente de la página de producto, nunca del snippet del buscador. Sin clave se declara el estado `not_configured`; no se simulan resultados.

`GET /api/offers?query=` consulta Brave y Mercado Libre de forma independiente. Devuelve `offers`, `needsReview`, `excludedCount` y `sources: {source,status,detail}[]`. Si ML falla, los resultados web sobreviven. Si ambas fuentes fallan, responde error explícito. Se persisten únicamente ofertas con precio actual publicado. La UI muestra título, tienda y enlace por producto y el estado de cada fuente.

Para consultas amplias, como «carpas», los resultados son productos relacionados: se muestran precios publicados pero no se afirma que las variantes sean idénticas ni que el primer precio sea la mejor compra. Envío, impuestos, disponibilidad y garantía quedan desconocidos si la fuente no los publica.

## Aceptación

- Búsqueda «carpas» descubre URLs reales desde el buscador y extrae precios estructurados de al menos dos tiendas en pruebas con respuestas simuladas.
- Un 403 de Mercado Libre no elimina los resultados web; ausencia de clave y fallos del buscador son visibles.
- URLs no permitidas, redirecciones, precio vencido, moneda no COP, producto ajeno y HTML excesivo quedan fuera.
- UI no destaca como ganadora una variante distinta y muestra el título de cada producto.
- Gates y CI verdes, revisión ajena y handoff.

## Handoff

- Comandos: `npm run lint`, `npm run typecheck`, `npm test` (96 pruebas), `npm run build` y `npm run features:check` verdes.
- Revisión ajena: `review_f022` detectó tres problemas (primer JSON-LD sin precio, consultas con «para», páginas halladas sin precio visible); quedaron corregidos y la segunda revisión no encontró bloqueantes.
- Archivos: adaptador de descubrimiento `src/lib/public-catalog.ts`, extractor estructurado en `src/lib/compare-link.ts`, agregación `/api/offers`, UI y pruebas; `BRAVE_SEARCH_API_KEY` documentada en `.env.example`. No hay credenciales en Git.
- Riesgo: no se ha ejecutado una búsqueda real con clave Brave porque todavía no existe `BRAVE_SEARCH_API_KEY` local. Cada búsqueda del usuario hace hasta tres consultas facturables de Brave; con US$5 de crédito (~1.000 consultas API) equivale a ~333 búsquedas de usuario/mes. Sitios que bloqueen lectura o no publiquen JSON-LD se muestran como enlaces sin precio verificado, no como ofertas.
- Siguiente paso: el propietario agrega `BRAVE_SEARCH_API_KEY` a su `.env` local y se hace smoke real de «carpas»; tras CI verde, solo el humano puede fusionar esta PR.
