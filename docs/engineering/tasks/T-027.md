## Contrato antes de implementación

`PriceSnapshot` conservará eventos de precio por producto, fuente, publicación y `capturedAt`. La clave única `(productId, source, offerId, capturedAt)` impide duplicar el mismo evento cuando se reintenta la escritura; una observación posterior sí generará historia. `POST` no se añade. `GET /api/offer-history?query=<variante>&mode=current|history&limit=1..50&cursor=<snapshot-id>` usa la misma clave canónica que el escritor. `current` devuelve la observación más reciente por `(source, offerId)` hasta el límite y señala truncamiento; `history` devuelve eventos ordenados por fecha descendente y cursor. La respuesta serializa importes decimales como cadenas, fecha ISO y confirmaciones; cuando no hay DB configurada responde 503 explícito y una consulta ambigua responde 400. No expone credenciales ni datos privados. `DATABASE_URL` seguirá siendo local/secret, nunca versionado. La configuración local debe permitir aplicar el esquema y ejecutar una prueba real de escritura/lectura si el servicio PostgreSQL está disponible.

La ampliación a más fuentes no se simulará como resultado automático: tendrá ticket aparte para conectores autorizados y aportes verificables. F-006 establece el almacenamiento y la lectura comunes.

## Aceptación

- PostgreSQL local tiene healthcheck y pasos de arranque/esquema documentados sin secretos versionados.
- Dos intentos del mismo snapshot no duplican filas; una captura posterior sí queda en la historia.
- API de lectura actual/histórica con filtros y límites validados, pruebas de paginación y sin conexión configurada.
- Se ejecutan lint, typecheck, tests, build y `features:check`; revisión ajena y CI verdes antes de `done`.
