- Objetivo: persistir observaciones válidas de precio cuando `/api/offers` responde exitosamente y hay `DATABASE_URL`, sin convertir errores de base de datos en resultados falsos o fallos de búsqueda.

## Contrato previo a implementación

`PriceSnapshot` pertenece a un `Product` mediante `productId`. Se añade `Product.canonicalKey` nullable y único para identificar la variante normalizada sin romper productos ya existentes. La clave incluye marca, modelo, capacidad y condición de la consulta, que ya son requisitos para una coincidencia inequívoca de F-007. Cada oferta comparada genera un snapshot con identificador de publicación (`offerId`), `source`, importes decimales `price`, `shipping`, `taxes`, `currency` y `capturedAt` derivado de `checkedAt`; índices `(productId, capturedAt)` y `(source, capturedAt)`. Un monto `unknown` del contrato conserva su cifra como mínimo observado, sin marcarlo confirmado en la tabla. F-006 definirá historial/auditoría e idempotencia; F-016 no ofrece aún lecturas públicas ni alertas.

Tras validar la respuesta de Mercado Libre, `GET /api/offers` intenta guardar los snapshots solo si `DATABASE_URL` está configurado y hay ofertas. `Product` se crea o reutiliza por `canonicalKey`. Un fallo de conexión/escritura se registra sin secretos y la respuesta HTTP 200 con ofertas verificadas no se altera. Un 401/403, error de red, respuesta inválida o ausencia de ofertas no genera snapshots. El endpoint conserva exactamente su JSON público.

Prisma 7 utiliza `prisma.config.ts` para la URL de CLI y el adaptador PostgreSQL para el cliente en runtime. `npm run db:generate` debe ejecutarse en CI y en la validación postmerge antes de typecheck/build. Sin `DATABASE_URL`, generar tipos y compilar sigue siendo posible; `db:push` y persistencia real requieren Postgres configurado. No se añade scraping ni se guardan enlaces aportados manualmente en este ticket.

## Aceptación

- Esquema `PriceSnapshot` con campos/índices, relación y clave canónica documentada; `db:generate` y `typecheck` pasan sin base de datos.
- Mapeo de ofertas validado y probado, con moneda y montos serializables coherentes con Prisma; consultas inequívocas y sus ofertas comparten el mismo producto.
- API guarda un snapshot por oferta solo con `DATABASE_URL` y respuesta exitosa; fallo de escritura no cambia status ni payload; fuente rechazada no escribe.
- Lint, typecheck, tests, build, features:check, revisión independiente y CI verdes; handoff antes de `done` y merge solo humano.
