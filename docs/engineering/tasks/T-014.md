# T-014 — Envío e impuestos reales desde Mercado Libre

- Feature: F-014
- Dueño: Claude
- Rama: `feature/t-014-ml-item-details`
- Estado: `claiming` → `in_progress` tras publicar draft PR.

## Objetivo

El conector actual (`src/lib/mercadolibre.ts`) devuelve `shipping = 0` y `taxes = 0`
para todos los resultados, y decide `estimated` solo por `free_shipping`. Esto
sesga el ranking: un ítem con envío pago aparece con el mismo total que uno
gratis. Necesitamos precio total honesto usando lo que la API expone por ítem.

## Alcance

- Enriquecer cada resultado con la API `GET /items/{id}` cuando esté disponible,
  o `GET /items/{id}/shipping_options?zip_code=...` si aplica.
- Extraer `price` publicado y `shipping.cost` (si la API lo expone en la búsqueda
  amplia sin necesidad de ZIP). No consultar por ítem si el resultado ya trae
  envío gratis explícito.
- Marcar `estimated = true` únicamente cuando el envío o los impuestos queden
  sin confirmar (no cuando estén en cero por ser realmente cero).
- Degradación: si la llamada de enriquecimiento falla o excede el timeout, se
  usa la respuesta base y se marca `estimated = true` sin romper la búsqueda.

## Fuera de alcance

- Impuestos calculados por región (no expuestos por la API pública).
- Persistencia histórica (F-016).
- Cambios de UI o de contrato en `src/lib/offers.ts`.

## Riesgos

- Rate limit de Mercado Libre al enriquecer N resultados en paralelo: mitigar
  con `Promise.allSettled` limitado a los 10 resultados del feed y fallback
  silencioso.
- Cambios en el shape de `/items` sin previo aviso: encapsular parseo en un tipo
  estrecho con validación mínima.
