## Diagnóstico y contrato

La ejecución https://github.com/camilocas88/price-radar/actions/runs/36655415221 sí identificó las PR #7 y #8 y generó las transiciones a `merged`. Falló en `npm run features:sync:test`: la prueba integral copia el archivo real F-004, que el workflow acababa de cambiar a `merged`, y esperaba una transición `[7]`. El fixture debe preparar explícitamente F-004 en `done` y no depender del estado vivo del registro. Cualquier otro feature `done` copiado debe quedar neutralizado en el fixture para que las PR futuras no hagan frágil esta prueba.

## Aceptación

- La prueba pasa con F-004 real en `done` y en `merged`; una ejecución repetida es idempotente.
- Gates del registro, lint, typecheck, tests y build verdes; PR y revisión ajena antes de `done`.
- Tras el merge humano, el workflow se reejecuta y se comprueba que F-004/F-018 pasan a `merged`.
