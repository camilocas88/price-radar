- Objetivo: permitir que el usuario pegue hasta seis enlaces de tiendas distintas, revise sus datos públicos o complete los faltantes, y compare solo variantes equivalentes; el flujo funciona aunque Mercado Libre responda 403.

## Contrato antes de implementación

Cada URL se inspecciona con el endpoint ya existente `POST /api/compare-link`, de forma secuencial y con el mismo límite de respuesta/tiempo, sin introducir búsqueda automática ni eludir bloqueos. El lote admite 2–6 URLs HTTPS de hosts expresamente permitidos; se añaden `mac-center.com` y `co.tiendasishop.com` como enlaces aportados, además de las cinco tiendas existentes. Un error de una URL no invalida las demás. La UI presenta cada borrador para confirmación humana; JSON-LD es dato publicado por la tienda pero no garantía de compra o disponibilidad. Ningún precio manual aparece como verificado.

Antes de indicar el precio menor, se compara la identidad normalizada de cada título confirmado con la referencia introducida por el usuario. Solo `match` participa en orden y diferencias; `review` o `mismatch` quedan visibles aparte con razón, sin contaminar el mínimo. Envío, impuestos e inventario siguen fuera del cálculo. Se utiliza el contrato de `normalizeProduct`/`compareProducts` sin cambiar módulos compartidos de F-006.

Limitación del normalizador actual: solo identifica modelos de iPhone. Los demás productos quedan `review`, no se fuerza una equivalencia falsa para mostrar un precio menor.

## Aceptación

- Entrada por lote de 2–6 URLs con progreso, errores por enlace y confirmación de borradores.
- Mac Center e iShop Colombia se aceptan por host HTTPS exacto; destinos o redirecciones no permitidos siguen bloqueados.
- Solo variantes `match` con precio positivo participan en el menor; mismatches/ambiguos se explican.
- Tests de lotes, dominios, variantes y fallos parciales; cuatro gates y CI verdes, revisión ajena y handoff.
